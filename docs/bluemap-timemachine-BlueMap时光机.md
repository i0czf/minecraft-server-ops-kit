# BlueMap 时光机（轻量快照 MVP）

BlueMap 时光机不是“把地图倒回昨天”的回滚按钮，而是 BlueMap 的**只读状态取证器**：把当前地图发布状态记录成可比较的快照，回答“哪张地图什么时候变了、是内容变化还是渲染刷新、在线数据是否更新”三个运维问题。它适合发布验收、卡顿/地图异常复盘和判断是否需要进一步保留历史瓦片。

## 这次截图里的结果是什么意思

截图中的旧版摘要是：`yellow · 7张地图 · 新增0/移除0/变化7 · 模式metadata`。含义是：7 张地图都还在，没有新增或删除，但旧算法把地图目录时间变化统一算成了“变化”。BlueMap 重渲染、服务重启或文件批处理都可能触发目录时间更新，这不等于世界数据损坏。

现已升级为指纹版本 3：目录时间和根目录文件的最新修改时间都不再单独触发内容变化；根目录改用“文件名+大小+SHA-256”聚合指纹，并新增“仅目录刷新”分类。算法升级后的第一次运行会显示 `baseline=true`，只建立新基线；之后若只是目录刷新，会显示 `内容变化0/仅刷新N` 并保持 `green`。只有地图新增、移除，或 settings/root 文件、live 指纹、`-Deep` 瓦片统计真正变化时，才会计入“内容/瓦片变化”并标黄。

因此，时光机目前的实际作用是：

- **发布前后验收**：确认地图数量、settings 和 live 指纹是否如预期变化。
- **异常复盘**：给事故报告提供某一时刻的地图索引和差异证据。
- **渲染降噪**：把“仅目录刷新”和真实内容变化分开，避免重渲染造成误报。
- **历史能力的安全前置**：先保存低成本索引，等磁盘配额和保留周期明确后，再决定是否保存瓦片版本。

它**不会**复制瓦片、恢复地图、回滚世界，也不会替代备份。

## 安全边界

- 只读 `bluemap\web`（也可用 `-SourceRoot` 指定其他 BlueMap web 根目录）。
- 默认只读取 `settings.json`、地图目录元数据和 `live\players.json` / `live\markers.json` 的大小、时间、SHA-256；不读取玩家坐标内容写入报告。
- 默认不扫描、不复制瓦片。`-Deep` 只统计 `tiles` 文件数、总大小和最新修改时间，仍不会复制或改写瓦片、世界、配置。
- 输出只写 `tmp\bluemap-timemachine\`，不会停 Minecraft，也不会重启 BlueMap。

## 使用方式

| 入口 | 用法 |
|---|---|
| 控制面板 | 「BlueMap 时光机」；默认轻量 metadata 模式 |
| 一键脚本 | `一键脚本\一键便携-BlueMap时光机.bat`；传 `deep` 做瓦片统计 |
| 命令行 | `powershell -File tools\bluemap-timemachine.ps1` |
| QQ 监控 | `!地图时光机` / `!bluemap-history`；管理员可追加 `deep` |

脚本常用参数：

- `-SourceRoot <目录>`：覆盖默认的 `bluemap\web`。
- `-Deep`：递归统计每张地图的瓦片数量、大小和最新时间；大目录耗时会明显增加。
- `-QqSummary`：只输出适合 QQ 的一行摘要。
- `-Json`：输出结构化 `meta.json` 内容。
- `-OutDir <目录>`：把本次四件产物写到指定目录。

## 产物

每次运行生成 `tmp\bluemap-timemachine\<时间戳>\`：

- `snapshot.json`：版本、扫描模式、来源、地图配置摘要、live 文件指纹和前一次快照差异。
- `report.md`：面向人的地图索引、差异和下一步建议。
- `summary-qq.txt`：短摘要，可直接发到 QQ/Discord。
- `meta.json`：红/黄/绿结果和稳定路径。
- `latest\`：上述四个文件的稳定副本。

### 差异字段

`report.md` 和 QQ 摘要使用以下口径：

| 字段 | 含义 | 是否标黄 |
|---|---|---:|
| 新增 | 上一次没有、本次出现的地图 | 是 |
| 移除 | 上一次有、本次消失的地图 | 是 |
| 内容/瓦片变化 | settings、地图根文件、live 指纹，或两次 `deep` 的瓦片统计发生变化 | 是 |
| 仅目录刷新 | 目录时间变化，但上述内容指纹未变化 | 否 |

模式切换（`metadata` ↔ `deep`）不会把所有地图批量误报为变化；只有连续两次都是 `deep` 才会比较瓦片统计。

## 当前实跑样本

已用连续两次 metadata 快照验收：首次建立 `baseline=true` 的绿色基线；内容不变的第二次快照仍为绿色，不会把目录时间或根文件时间刷新误报为地图变化。指纹版本 3 已消除这类噪声。MVP 不默认复制可能很大的渲染瓦片目录。

真正的历史地图浏览仍需要后续制定磁盘配额、保留周期和瓦片版本目录；在这之前，快照索引已经能为事故复盘和发布验收提供可追溯的地图状态证据。

# 事故自动复盘

事故自动复盘是一个只读的证据关联器：把时间线、性能黑匣子、卡顿取证、错误指纹、高危审计、崩溃报告和备份验证放进同一个窗口，输出可读的 Markdown 复盘，而不是只报“有 ERROR”。

## 安全边界

- 不停 Minecraft，不改配置，不写世界，不自动回滚。
- “高/中”表示证据需要优先人工复核，不代表脚本已经证明根因。
- 崩溃、非零退出、卡顿和错误指纹按时间窗口关联；同一启动阶段的重复指纹会聚合，避免一条模组问题刷成十几个事故。
- 报告和 QQ 摘要会过滤服务端根路径、Token、密码、Webhook、API Key 与 IP。

## 使用方式

| 入口 | 用法 |
|---|---|
| 控制面板 | 「事故复盘」；默认最近 24 小时，输出新窗口 |
| 一键脚本 | `一键脚本\一键便携-事故自动复盘.bat [1h\|6h\|24h\|7d]` |
| QQ 监控 | `!复盘` / `!postmortem`；可追加 `1h`、`6h`、`24h` 或 `7d`，返回短摘要 |
| 命令行 | `powershell -File tools\incident-postmortem.ps1 -Window 24h` |

脚本参数：

- `-Window 1h|6h|24h|1d|7d`：证据窗口，默认 `24h`。
- `-MaxIncidents N`：最多输出多少张事故卡，默认 12。
- `-QqSummary`：只输出适合 QQ 的短摘要。
- `-Json`：额外输出压缩后的 `meta.json` 到标准输出。

## 产物

每次运行生成 `tmp\incident-postmortem\<时间戳>\`：

- `report.md`：完整复盘，含结论、指标、事故卡、证据和人工建议。
- `summary-qq.txt`：短摘要，可直接复制到 QQ/Discord。
- `meta.json`：结构化计数、严重度、事故卡和报告路径。
- `latest\`：上述三个文件的稳定副本，供面板或后续自动化读取。

## 关联逻辑

| 证据 | 触发的复盘卡 |
|---|---|
| `crash-reports\crash-*.txt` | 崩溃：高，附报告头部和最近时间 |
| wrapper 非零退出 | 异常退出：高，提示核对 JVM/模组/外部杀进程 |
| `tmp\lag-forensics\*\meta.json` 或时间线卡顿事件 | 卡顿：中，附 MSPT/TPS/在线/线程转储/Spark 状态 |
| 时间线新指纹 ≥ 3 条 | 指纹集中：中，按归一化文本聚合 Top 项 |
| 备份验证明确出现“失败 N（N>0）” | 备份验证失败：高，提示停止信任该恢复点 |

计划重启、正常退出、备份完成和验证通过会进入指标与证据，但不会单独判成事故。

# QQ 要素物品反查：运行时真值索引

## 结论

采用“摘要图片 + 折叠完整清单 + 按需单页”三层交互，不把 TXT 持久上传到群文件：

| 群命令 | 只产生 | 用途 |
|---|---:|---|
| `!矿藏` | 1 张 PNG | 日常快速看总数、要素量最高的前 24 项和快照时间 |
| `!矿藏 全部` | 1 个合并转发气泡 | 点开查看、搜索和复制全部结果，不占群聊多屏 |
| `!矿藏 2` | 1 条文字 | 低带宽、图片打不开或只想逐页看；每页 14 项 |

`全部`、`完整`、`所有`、`txt`、`text`、`文本` 都进入同一个折叠完整清单，不会逐条发送，也不会向群文件留下长期附件。

还支持显式写法 `!要素物品 矿藏`、`!物品要素 矿藏`、`!要素来源 矿藏`，以及拉丁标签写法 `!aspectitems perfodio`。原有 `!要素 矿藏` 仍用于查询要素自身的合成关系，两个功能互不覆盖。未知的 `!某词` 不会被误吞，只有能解析成已注册要素时才按简写处理。

要素别名若与旧命令冲突，旧命令永远优先。例如 `!合成 箱子` 仍查配方，`!天气 晴` 仍改天气；要反查“合成”或“气候”要素时写 `!要素物品 合成`、`!要素物品 气候`。

## 为什么这样最合逻辑

问题里有三个彼此拉扯的目标：数据必须全、日常回复必须轻、需要时又必须能复制完整结果。

- 单发 TXT 虽然完整，但手机端预览和检索体验差，还会在群文件留下持久资源；每次模组更新后旧附件也容易被误认成最新数据。
- 把结果逐条或逐页主动发完虽然完整，却把机器人的信息成本转嫁给所有群友，必然刷屏。
- 只发图片很安静，但图片不是完整数据载体，物品 ID 不便复制；结果超过 24 项时也放不下。
- 因此默认图片负责“扫一眼”，合并转发负责“完整但折叠”，页码负责“明确请求才展开一页”。无论哪条命令，群主时间线里都只新增一个消息气泡。

## 真值从哪里来

`qq-aspect-indexer` 是一个很小的纯服务端 NeoForge 旁路模组。它不维护物品白名单，也不从文件名猜当前模组版本，而是在当前 JVM 完成加载后执行：

1. 取当前服务端的 `RecipeManager` 和注册表访问器，并显式绑定给 Thaumcraft。
2. 枚举 `BuiltInRegistries.ITEM` 中除空气外的每个已注册物品，构造其默认 `ItemStack`。
3. 直接调用当前已加载 Thaumcraft 的 `ItemAspectRegistry.getObjectTags`；这与该版本 JEI 的要素来源枚举路径一致。
4. 从 NeoForge `ModList` 读取真正已加载的模组版本、文件与 `zh_cn.json`，而不是扫描 `mods` 目录里可能共存的旧版 JAR。
5. 先写临时文件，再原子替换 `tmp\item-aspects.tsv`。QQ 桥按文件时间和大小自动失效缓存，无需再重启机器人。

索引在每次正常开服后生成；执行 `/reload`、数据包或配方重载后也会重新生成。若重载发生在导出途中，旧导出不会发布，工作线程会用最新 RecipeManager 再算一遍。

模组升级的真实生效边界仍然是“下一次 JVM 启动”：只把新 JAR 放进 `mods` 而不重启，本来就不可能改变当前 JVM 内已加载的注册表。本功能不会为了更新索引强制踢玩家或重启服务器；下次自然开服时会自动跟随新模组重建。

## “最新、真实、最全”的精确定义

这里的全集是“当前运行时注册表中，每个物品的默认形态”。这是一个可枚举、可复现，并且与 JEI 展示口径一致的集合。

带任意 NBT、耐久、药水内容、附魔或模组动态组件的 `ItemStack` 变体理论上可能无限多，无法声称穷举。因此不会用“所有可能 NBT 变体”这种无法兑现的口径。若以后要查某个手持物品的具体 NBT 形态，应另做“按玩家手中物品查询”，不能混进本索引。

每个物品单独容错。若某个模组物品计算要素时抛错，快照会记录 `failedItemCount`，图片和完整清单明确提示有多少项失败；系统宁可承认缺口，也不会把残缺结果标成完整。快照还记录生成时间、触发原因、配方数、注册物品数和实际已加载模组指纹，便于审计。

## 文件与运维

- 模组：`mods\qq-aspect-indexer-1.0.0.jar`
- 源码：`tools\item-aspect-indexer\src\main\java\com\chesir\qqaspectindex\QQAspectIndexMod.java`
- 构建：`powershell -ExecutionPolicy Bypass -File tools\build-item-aspect-indexer.ps1 -Deploy`
- 运行时快照：`tmp\item-aspects.tsv`
- QQ 摘要图缓存：`tmp\qq-aspects\item-cards\`
- 名称兜底表：`tmp\recipe-index\item-names.tsv`

正常日志应出现：

```text
[qqaspectindex] 运行时物品要素索引已更新，trigger=server-start
```

执行 `/reload` 后对应 `trigger=data-reload`。若快照还未生成，QQ群命令只回复一条明确说明，不会用旧的离线猜测数据冒充当前服数据。

生成快照后可在本机离线验证，不会连接 QQ：

```powershell
java -Dfile.encoding=UTF-8 -cp tmp\java-classes QQConsoleBridge --aspect-items 矿藏
```

它会打印匹配结果并生成同款摘要图。群内验收只需等自然启动后由群友正常查询，不应为了测试连续发送多条命令。

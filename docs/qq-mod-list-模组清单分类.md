# QQ !mods 分类模组清单

## 功能目标

!mods 面向玩家展示当前服务端的模组组成。输出重点从“文件名堆叠”调整为“先看玩法，再看关系”：

1. 先展示直接改变世界内容的玩法模组；
2. 再展示玩法扩展、兼容和联动模组；
3. 然后展示玩家体验、性能和服务器管理能力；
4. 最后集中展示前置库与暂时无法识别的项目。

这样玩家可以先回答“这个服玩什么”，需要排查启动依赖时，再继续查看前置和关联关系。

## 玩家用法

以下命令都指向同一份清单：

~~~text
!mods
!mod
!modlist
!模组
!模组列表
!模组清单
!mod列表
!mod清单
~~~

命令不需要参数，读取目标服务端的 mods/*.jar。分类结果来自本地 JAR 元数据和已安装文件，不依赖外部百科接口，也不会为了列清单执行 RCON。

## 分类顺序

| 分类 | 玩家理解 | 典型内容 |
|---|---|---|
| 🎮 玩法内容 | 直接增加可玩的内容 | 世界、物品、生物、维度、魔法、科技、冒险系统 |
| 🔗 玩法扩展与兼容 | 围绕主玩法工作的附加内容 | 联动、兼容、整合、升级器、扩展包 |
| ✨ 玩家体验与信息 | 让游玩和查询更方便 | 指南、查询、聊天、视觉、媒体、便利功能 |
| ⚡ 性能优化 | 改善运行效率或提供诊断 | 性能优化、资源占用控制、性能诊断 |
| 🛡️ 服务器管理与本服定制 | 服务端侧的管理能力 | 权限、安全、清理、地图服务、建筑管理、运维工具 |
| 🧩 前置与库 | 主要为其他模组提供基础能力 | API、配置库、通用库、网络或渲染依赖 |
| 📦 其他/待识别 | 保留不确定项，避免武断误分类 | 元数据缺失、名称不明确或新模组 |

分类不是把一个模组硬塞进多个栏目：每个 JAR 只有一个主分类，具体用途通过“类型”和关系字段补充。顺序优先保证玩家阅读体验，未知项目留在最后方便维护者复核。

## 单项展示

清单会尽量显示以下信息：

~~~text
• 本地显示名 v版本 〔子类型〕
  前置：必需的已安装依赖
  关联主模组：从元数据或已知兼容关系推断出的主玩法
  可选联动：已安装的可选依赖
  文件：服务器中的实际 JAR 文件名
~~~

- 版本优先读取 JAR 内的本地元数据；
- 必需前置未安装时会明确标记；
- 仅客户端侧的依赖会标记为“客户端前置，服务端未安装”，避免被误判为服务端缺包；
- 前置库会反向显示“被使用”的模组，排查缺依赖时不必逐个猜；
- 同一个 JAR 提供多个模组 ID 时，会保留这些 ID 用于依赖匹配；
- 元数据损坏时不影响整张清单，至少保留文件名。

## QQ 消息体验

清单较短时直接发送一条消息；较长时只发送一个可折叠的合并转发消息，节点内部按分类和长度分段。这样群里不会连续刷出几十条消息，玩家仍能展开查看完整内容。

如果当前 OneBot 实例不支持合并转发，机器人会退化为少量分段消息，并在首段说明原因。单个分类过长时会出现“续”页，不会截断到只剩分类标题。

## 元数据来源与识别原则

当前按以下顺序寻找模组元数据：

- META-INF/neoforge.mods.toml
- META-INF/mods.toml
- fabric.mod.json
- mcmod.info

识别采用“本地事实优先、启发式只做补充”的原则：

1. 先读取模组 ID、显示名、版本、必需/可选依赖和运行侧；
2. 再用通用的用途词和已知公开模组 ID 细化子类型；
3. 只有依赖玩法模组，或名称明确表示兼容/整合时，才进入扩展分类；
4. 通用库不会因为被玩法模组依赖就被误列为玩法；
5. 无法确认时保留到“其他/待识别”，不伪造结论。

这套逻辑适合不同整合包，模组数量和具体分类会随目标服务端变化。

## 离线检查

在仓库根目录可先独立编译 QQ 桥：

~~~powershell
New-Item -ItemType Directory -Force .\tmp\javac-check | Out-Null
javac --add-modules jdk.httpserver -encoding UTF-8 -d .\tmp\javac-check .\tools\QQConsoleBridge.java
~~~

在实际服务端目录中，可以不连接 QQ 预览分类：

~~~powershell
java -cp .\tmp\javac-check QQConsoleBridge --mods-preview .\tools\ops-config.json
~~~

预览只读取本地 mods 目录和 JAR 元数据，不发送 QQ 消息、不调用 RCON、不写入配置。

## 公版隐私边界

公开仓库只提交通用源码、模板和本说明，不提交运行中的 mods/、日志、世界、备份、QQ 消息、群号、账号、域名、Token 或本机绝对路径。真实服务端请使用自己的私有配置和运行目录；不要把整个运行中的服务端目录直接上传。

如果私服需要增加特殊分类，应在私有部署中维护对应的公开模组 ID 或通用关键词；不要把私服名称、群身份或其他可识别信息写进公版源码。

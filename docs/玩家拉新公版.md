# Minecraft 玩家拉新与增量更新公版

这是从完整腐竹运维工具包拆出的独立功能包，只解决一件事：让任意 Minecraft 服务器从自己的主客户端生成玩家更新源、规范导入包、完整懒人包，并让玩家后续增量更新与自助修复。

它不包含 QQ/Discord 机器人、备份、RCON 运维、世界数据，也不预设作者服务器的域名、群号、账号或密钥。首次使用必须填写自己的配置。

## 最短上手路线

1. 把本包解压到你的 Minecraft 服务端根目录。
2. 双击 `一键脚本\一键拉新-初始化配置.bat`，选择你的主分发客户端实例，填写整合包名、玩家地址和更新服务公网地址。
3. 双击 `一键脚本\一键拉新-生成规范导入包.bat`，得到 `.mrpack` 与 PCL 客户端包；这是日常拉新首选。
4. 需要传统“小同步包”（玩家解压后再运行同步器）时，双击 `一键脚本\一键拉新-生成玩家同步包.bat`。
5. 大型资源、枪皮、光影等需要一次性随包时，双击 `一键脚本\一键拉新-生成完整客户端包.bat`。
6. 双击 `一键脚本\一键拉新-开启更新服务.bat`，并只对外放行配置的 TCP 端口。不要开放 RDP、SMB 或文件共享端口。
7. 日后主客户端有变更，双击 `一键脚本\一键拉新-仅发布更新.bat`；玩家用随包的更新入口启动即可增量同步。

## 安全边界

- `tools\portable-pack.json` 只存目标服务器的整合包身份、客户端路径、更新地址与同步策略；不要在里面写 QQ、Discord、API Key 或系统账号密码。
- 更新服务自动生成随机路径令牌并保存在 `.update-server-token`；该文件是本机私有运行数据，不应分享。
- 玩家自己的键位、存档、截图、资源包、光影和自定义目录按模板默认保护；修改同步范围前先读清 `preserve*`、`additiveDirs` 和 `force*` 的含义。
- 发布目录和压缩包输出被限制在解压后的服务端根目录内，避免错误配置写到其他磁盘位置。
- 建议先用测试客户端导入、更新、自助修复各跑一遍，再把包发给玩家。

## 产物

- `dist\<名称>-standard-import-<版本>.mrpack`：PCL/HMCL/Prism 规范导入。
- `dist\<名称>-PCL-client-<版本>.zip`：完整 PCL 结构客户端。
- `dist\<名称>-full-client-<版本>.zip`：包含 `fullPack.extraRoots` 大件的完整懒人包。
- `modpack-public\portable\`：增量更新服务读取的发布目录。

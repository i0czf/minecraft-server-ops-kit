# v0.3.1 · QQ 绑定提醒、游戏 @ 与转发开关

这是 `v0.3.0` 绑定能力的增强，不另开大版本。接到现有 QQ 桥和日志监控上，不引入 MCDR，也不另起机器人。

## 新增

- **`!转发 开|关`**：管理员立刻停/恢复 QQ↔游戏双向聊天。进退服、成就、备份、崩溃通知还在；`!` 命令和 `@AI` 不受影响。状态写在 `logs/qq-chat-relay.json`，热重载 QQ 桥后还记得。非管理员只能查状态。
- **绑定提醒**：没绑的人在主群说闲话，大约 5 秒后轻提一句去 `!绑定`，同一人默认 6 小时只提一次。管理员发 `!绑定提醒` 看开关，`!绑定提醒 开|关` 立刻改，`!未绑定` 列最近说过话但没绑的人。公版模板默认关；主群不全是玩家时建议保持关。
- **游戏 `@游戏ID` → 群里真 @QQ**：游戏公屏喊 `@Steve`，主群这条 `[聊天]` 会点到绑定这个 ID 的 QQ。没绑的名字保持原文；邮箱和网址里的 `@` 不会乱点。进退服、成就、崩溃通知不解析 `@`。

## 使用要点

| 命令 | 谁 | 作用 |
|---|---|---|
| `!转发` | 全员可查 | 看聊天转发开还是关 |
| `!转发 关` / `!转发 开` | 管理员 | 立刻停/恢复双向聊天 |
| `!绑定提醒` | 管理员 | 看提醒开关、冷却、本进程已提醒人数 |
| `!绑定提醒 关` / `开` | 管理员 | 立刻停/恢复未绑定轻提醒 |
| `!未绑定` | 管理员 | 最近主群说过话但没绑的人 |

游戏侧只需在公屏发 `@已绑定ID`。监控脚本读绑定仓库，把 `@Name` 改成 OneBot CQ `@` 再推群。

## 配置

公版模板 `playerBind.enabled` 和 `remindUnbound` 都默认 `false`：

```json
{
  "playerBind": {
    "enabled": false,
    "remindUnbound": false,
    "remindCooldownMinutes": 360
  }
}
```

`!转发` 和 `!绑定提醒` 的运行时开关不进 `ops-config.json`，分别是 `logs/qq-chat-relay.json` 和 `logs/qq-bind-remind.json`。

改 QQ 桥只热重载；动到 `discord-watch.ps1` 再热更运维监控。不要冷启动 Minecraft。

功能说明：[QQ 号与游戏 ID 绑定](https://github.com/i0czf/minecraft-server-ops-kit/blob/main/docs/qq-player-bind-%E6%B8%B8%E6%88%8FID%E7%BB%91%E5%AE%9A.md)

## 验证

- NeoForge 1.21.1 / 21.1.235 实服已验收：`!转发`、绑定提醒开关、游戏 `@已绑定ID` 点到 QQ。
- `QQConsoleBridge --bind-selftest` 覆盖 `@Name` 切段、冷却跳过已绑定、转发开关读写。
- 游戏 `@` 走 CQ 字符串，与 QQ 桥同一条发送路径；数组 at 在 2 秒超时里丢过消息，不再作为现网路径。
- 公版文件隐私扫描通过：无真实域名、IP、群号、令牌或绑定仓库。
